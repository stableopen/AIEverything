# AIEverything UI 参考与视觉设计

日期：2026-07-17
范围：只调整 `App.xaml` 与 `MainWindow.xaml` 的视觉层、布局和已有交互状态；不改变业务逻辑、控件名称、事件处理器或搜索行为。

## 基线审阅

审阅了 0.4 已发布界面（1320 × 820 窗口、中文 Windows、高 DPI）和对应 XAML。现有版本已经具备搜索、筛选、索引状态、授权目录与结果操作的完整功能，但仍有以下体验问题：

- 搜索框、筛选器、品牌区的视觉重量接近，第一眼主任务不够集中。
- 默认窗口偏大；在常见小屏或高 DPI 环境中容易逼近屏幕边缘。
- 左侧状态卡中标题、状态、目录、操作的间距较松，同屏有效信息偏少。
- 结果表虽然清晰，但列头、行、悬停、选中和可操作状态的反馈不够统一。
- 按钮、输入框、列表、空状态的圆角、颜色和边框语义还未形成完整设计系统。
- 控件只有视觉标签，筛选器和搜索主入口缺少明确的辅助功能名称。

## 参考产品与可迁移原则

### 1. Everything

来源：[Everything 官方搜索文档](https://www.voidtools.com/support/everything/searching/)

可迁移原则：

- 搜索结果保持表格式高密度展示，文件名、路径、时间、大小能够横向快速扫读。
- 类型、路径、时间等筛选应靠近搜索入口，并支持键盘完成主要流程。
- 状态信息适合放在边缘区域，持续可见但不抢占主操作。

不直接照搬：Everything 的菜单和高级搜索语法更适合专家用户；AIEverything 保留可点击中文筛选，降低学习成本。

### 2. Microsoft PowerToys Run

来源：[Microsoft Learn：PowerToys Run](https://learn.microsoft.com/windows/powertoys/run)

可迁移原则：

- 搜索输入是界面唯一明确的第一主操作。
- 输入、结果与执行动作之间的距离要短，键盘焦点状态必须明显。
- 结果动作按当前选择启用，减少无效操作干扰。

不直接照搬：PowerToys Run 是瞬时浮层；AIEverything 还承担授权目录和索引健康管理，因此将管理能力保留在按需展开的侧栏中，默认仍是轻量搜索工具。

### 3. Flow Launcher

来源：[Flow Launcher 官方网站](https://www.flowlauncher.com/)

可迁移原则：

- 使用克制的中性色和单一强调色，让关键词与结果内容成为视觉中心。
- 键盘优先，但不能牺牲鼠标用户的悬停、选中和快捷动作反馈。
- 信息按“标题、辅助说明、动作”建立稳定层级，不依赖装饰制造层级。

### 4. Listary

来源：[Listary 官方文件搜索页](https://www.listary.com/file-search)

可迁移原则：

- 输入时即时反馈；文件类型、修改时间等常用条件使用可点击筛选，不要求用户记忆语法。
- 搜索结果旁提供打开、定位、复制路径等就地操作。
- 路径信息必须可见，但弱于文件名，避免长路径压过主要内容。

## 落地设计

### 视觉系统

- 字体：优先 `Segoe UI Variable Text`，回退 `Segoe UI` 和 `Microsoft YaHei UI`，兼顾 Windows 11 与中文显示。
- 强调色：使用接近 Windows Fluent 的克制蓝色 `#0F6CBD`；成功、警告、危险只用于语义状态。
- 表面：工作区 `#F3F5F8`，卡片白色，次级区域 `#F7F9FC`，通过 1 px 边框而非重阴影分层。
- 圆角：卡片 10 px、输入 8 px、按钮 6 px，减少旧版多个不同半径带来的不一致。
- 密度：第二轮先将默认窗口收敛为 960 × 620，真实 175% DPI 验收后进一步调整为 900 × 560；最小仍为 820 × 520。索引侧栏默认收起，搜索结果占据整个主体。

### 搜索主操作

- 搜索框使用 46 px 高度、蓝色搜索图标和清晰焦点描边。
- `Enter` 键提示放入搜索框右侧，立即搜索按钮保持唯一实心主按钮。
- 四个筛选器紧贴搜索框下方；快捷键提示退居最右侧。
- 所有筛选器和搜索输入增加中文 `AutomationProperties.Name`。

### 索引与授权目录

- 顶部“索引目录”按钮控制侧栏；默认 `IndexPanelColumn=0` 且 `IndexPanel=Collapsed`，不让低频管理功能挤占搜索空间。
- 展开后的左栏仍分为“索引状态 / 本机搜索服务”和“正文索引目录”两个明确段落。
- 状态卡压缩字号与间距，正文服务和 Everything 状态仍同时可见。
- 目录项使用统一的文件夹图标底板，并增加悬停、选中、焦点反馈。
- 隐私说明用低饱和绿色语义卡表示“本地保存”，不作为广告式横幅。

### 结果区

- 结果工具按钮降为浅色三级动作，只有选中结果后才成为可用状态。
- 表头高度 40 px，结果行最小 60 px；行悬停为浅灰蓝、选中为浅蓝。
- 文件名保持主文本，路径使用 10 px 辅助文本；类型使用小型描边标签。
- 保留 Everything 式表格密度，并为正文片段留出更大比例宽度。
- 欢迎态增加“输入即搜索 / 双击打开 / 内容不上传”三条简短能力提示；空结果态提供明确恢复动作。

## 兼容性与边界

- 保留全部现有 `x:Name`、事件处理器名称和 Binding 字段。
- 不新增业务交互，不改变 320 ms 防抖、搜索模式、目录管理或结果动作。
- 不引入外部 UI 框架、字体、图片或网络资源，界面仍可完全离线运行。
- 本轮不实现深色模式、预览窗格和窗口自定义标题栏；这些需要更多代码状态或更大交互设计，应另行评估。

## 验证记录

- 审阅 0.4 已发布窗口的 1320 × 820、高 DPI 基线截图，确认默认窗口和字号在小屏上的空间压力。
- 第一轮曾以 1180 × 760 验证双栏；第二轮根据“小而精美的小工具”定位，改为单结果主视图，并将索引管理改为按需展开。
- 第二轮分别渲染 960 × 620 默认搜索视图和 292 px 索引侧栏展开视图；两种状态均无布局遮挡，默认态结果区占满主体。
- 在 1080p、175% DPI 的真实发布版上复验后，960 × 620 逻辑尺寸接近满屏，因此最终默认尺寸降为 900 × 560；侧栏展开、搜索与结果区仍保持完整。
- 900 × 560 首次实机截图发现目录列表被状态卡挤压，随后压缩状态卡、操作区和本地隐私提示的垂直间距；复验时授权目录项完整可见。
- 契约检查通过：34 个原有 `x:Name` 与 17 个原有事件处理器全部保留；新增 `IndexPanelColumn`、`IndexPanel`、`IndexPanelToggleButton` 和唯一的新切换事件。
- `dotnet build src\AIEverything.App\AIEverything.App.csproj -c Release` 通过：0 个警告、0 个错误。
